# Redis 未授权访问实验命令记录
# 实验环境：Vulhub + Docker Desktop
# 操作系统：Windows 11
# 漏洞类型：Redis Unauthorized Access
# 说明：本文件记录本次实验中使用到的安全验证命令，不包含破坏性操作。

==================================================
1. 下载 Vulhub
==================================================

cd /d E:\
git clone --depth 1 https://github.com/vulhub/vulhub.git

作用：
下载 Vulhub 漏洞环境集合。

说明：
Vulhub 是一个基于 Docker 的真实漏洞复现环境集合，适合用于学习真实漏洞和 CVE 漏洞复现。

--------------------------------------------------

==================================================
2. 进入 Redis 未授权访问目录
==================================================

cd /d E:\vulhub\redis\4-unacc

作用：
进入 Redis 未授权访问漏洞环境目录。

如果目录不存在，可以执行：

dir E:\vulhub\redis

查看 redis 目录下的具体漏洞环境名称。

--------------------------------------------------

==================================================
3. 启动漏洞环境
==================================================

docker compose up -d

作用：
使用 Docker Compose 启动 Redis 未授权访问漏洞环境。

说明：
-d 表示后台运行容器。

--------------------------------------------------

==================================================
4. 查看容器运行状态
==================================================

docker ps

作用：
查看 Redis 容器是否正常运行，以及 6379 端口是否映射成功。

重点观察：
1. Redis 容器是否处于 Up 状态；
2. 是否存在 6379/tcp 端口；
3. 是否存在类似端口映射信息：

0.0.0.0:6379->6379/tcp

实验中 Redis 容器名称为：

4-unacc-redis-1

--------------------------------------------------

==================================================
5. 使用本机 redis-cli 连接 Redis
==================================================

redis-cli -h 127.0.0.1 -p 6379

作用：
使用 Windows 本机安装的 redis-cli 连接本地 6379 端口上的 Redis 服务。

说明：
如果能够直接进入 Redis 命令行，说明 Redis 服务可以被连接。

进入后提示符可能类似：

127.0.0.1:6379>

--------------------------------------------------

==================================================
6. 使用容器内 redis-cli 连接 Redis
==================================================

如果 Windows 本机没有安装 redis-cli，可以直接使用 Redis 容器内置的 redis-cli。

先查看容器名：

docker ps

本实验中的容器名为：

4-unacc-redis-1

因此执行：

docker exec -it 4-unacc-redis-1 redis-cli

作用：
进入 Redis 容器内部，并启动容器内置的 redis-cli 工具。

进入后提示符可能类似：

127.0.0.1:6379>

说明：
这种方式不需要在 Windows 本机额外安装 redis-cli。

--------------------------------------------------

==================================================
7. PING 测试
==================================================

在 Redis 命令行中执行：

ping

预期结果：

PONG

作用：
测试 Redis 服务是否可以正常通信。

安全含义：
如果无需输入密码即可执行 ping 并返回 PONG，说明 Redis 可以在未认证情况下被访问。

--------------------------------------------------

==================================================
8. INFO 查看 Redis 信息
==================================================

INFO

作用：
查看 Redis 服务器信息、版本信息、系统信息、连接信息等。

安全含义：
如果无需认证即可执行 INFO，说明 Redis 服务存在信息泄露风险。

说明：
INFO 返回内容较多，通常包含 Redis 版本、运行模式、系统信息、客户端连接信息、内存使用情况等。

--------------------------------------------------

==================================================
9. DBSIZE 查看 Key 数量
==================================================

DBSIZE

预期结果示例：

(integer) 0

作用：
查看当前 Redis 数据库中 Key 的数量。

安全含义：
如果无需认证即可查看数据库状态，说明 Redis 访问控制不足。

--------------------------------------------------

==================================================
10. SET 写入测试数据
==================================================

SET testkey hello_vulhub

预期结果：

OK

作用：
写入一个测试 Key。

安全含义：
如果无需认证即可写入数据，说明 Redis 存在未授权写入风险。

说明：
本实验只写入普通测试数据，不进行破坏性操作。

--------------------------------------------------

==================================================
11. GET 读取测试数据
==================================================

GET testkey

预期结果：

"hello_vulhub"

作用：
读取刚刚写入的测试数据。

安全含义：
如果无需认证即可读取数据，说明 Redis 存在未授权读取风险。

==================================================

作用：

说明：

--------------------------------------------------

==================================================
14. Redis 未授权访问成功条件
==================================================

Redis 未授权访问通常需要满足：

1. Redis 服务正在运行；
2. Redis 默认端口 6379 可访问；
3. Redis 没有设置认证密码；
4. 防火墙或安全组没有限制访问来源；
5. 客户端可以直接连接 Redis；
6. 无需 AUTH 即可执行 Redis 命令。

--------------------------------------------------

==================================================
15. Redis 未授权访问风险
==================================================

可能造成的风险包括：

1. 缓存数据泄露；
2. 业务数据被读取；
3. Redis 数据被篡改；
4. Redis 数据被删除；
5. 服务稳定性受到影响；
6. 敏感配置或业务状态泄露；
7. 在错误配置情况下可能进一步扩大攻击面。

--------------------------------------------------

==================================================
16. 防御方式
==================================================

常见防御方式：

1. 设置 Redis 访问密码；
2. 不将 Redis 暴露到公网；
3. 使用防火墙或安全组限制访问来源；
4. Redis 绑定到 127.0.0.1 或内网地址；
5. 关闭不必要的端口映射；
6. 重命名或禁用高风险命令；
7. 使用最小权限原则运行 Redis；
8. 监控 Redis 访问日志；
9. 定期扫描开放端口。
